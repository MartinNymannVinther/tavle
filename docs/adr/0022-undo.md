# ADR 0022: Undo — every action can describe its own reverse

Status: proposed · Date: 2026-09-14 · Not built; the plan awaits the owner's go

## Context

The owner wants to always be able to undo an action. Today the safety
net is prevention (confirm dialogs, deactivate-instead-of-delete, the
close conversation) and record (the append-only audit log holds every
row image, the event log holds who did what). Neither is a way _back_.

## Decision (proposed)

**V1: undo the last action, offered where it happened.** Every
mutating server action gains an _undo description_: the minimal
inverse, named at write time when the "before" is in hand — a move
knows the column and index it left, a placement knows the old parent,
an archive knows it was alive, a field write knows the old value. The
action answers it to the client; the toast that already confirms the
action gains a "Fortryd" button that runs the inverse through the same
ordinary services (validated, rule-checked, event-logged as its own
action — an undo is a new action, not an erasure; the history stays
honest).

Scope of v1, deliberately: card moves and swimlane drops, placements
(feature/epic/parent), sprint commits, archive/restore, the plain field
edits, item quarter spans. Outside v1: deleting a board or workspace
(confirm dialogs remain the guard; restoring a whole board is a
different machine), closing an item (rule 10 is a conversation, its
reverse is the reopen button that already exists), and AI applies
beyond the row-level undos they decompose into.

**Later, if v1 earns it: the audit log as a time machine.** Row images
exist for everything; a "restore this row to how it stood at T" needs
conflict rules (what if others built on top?) and belongs to its own
ADR after real use of v1.

## Trade-offs to accept

- An undo description per action is a discipline on every new action,
  like the RLS test is on every new table. A meta-test should enforce
  that the wired actions answer one.
- "Undo" that re-runs services can be _refused_ by a rule that has
  since started to bind (the slot closed, the item closed). The toast
  then says why, honestly, instead of pretending the past is a file
  that can simply be put back.

## Plan (when approved)

1. `UndoDescription` type + `Result` extension; action helper carries it.
2. Toast component: action word + "Fortryd", 10 s, one level deep.
3. Wire the v1 scope, one action family per commit, tests per inverse.
4. Meta-test: every action in the v1 list answers an undo description.
